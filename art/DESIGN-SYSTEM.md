# BABYLAND — дизайн-система куклы

Как это устроено у всех, кто делал одевалки, и как поэтому устроено у нас.

## Закон

**Риг владеет позицией. Арт делается под риг.**

- **LPC** (Universal LPC Spritesheet Generator) — каждый ассет лежит на одной и
  той же фиксированной сетке и нарисован поверх общей базы. Выравнивание
  **запечено в картинке**. Категории описаны в `sheet_definitions/*.json`, у
  каждого слоя объявлен `z-position`, все z сведены в одну таблицу, чтобы
  стопку было видно целиком. Один ассет может иметь несколько слоёв на разных
  z — так решаются волосы спереди и сзади.
- **Spine / DragonBones** — слот это именованный контейнер на кости, и у слота
  **нет собственной позиции**: она приходит от рига.

Чего никто не делает: не вычисляет посадку в рантайме, впихивая bounding box
вещи в прямоугольник слота. Именно это делала первая версия нашего `fit()` —
отсюда и «вещи не стыкуются»: подол топа и пояс юбки ничего не знали друг о
друге, и каждая вещь требовала ручных поправок.

## Наш риг

Полотно **600 × 1200**, вертикальная осевая по центру. Риг — не коробки, а
**именованные линии тела** (доли от высоты полотна), измеренные по базе:

| линия | что это |
|---|---|
| `head_top` | макушка |
| `eye_line` | линия глаз — по ней садится мимика и макияж |
| `chin` | подбородок |
| `neck` | основание шеи |
| `shoulder` | линия плеч |
| `chest` | грудь |
| `waist` | талия |
| `hip` | бёдра |
| `knee` | колено |
| `ankle` | щиколотка |
| `sole` | подошва, пол |

## Как садится вещь

Вещь объявляет не координаты, а **между какими двумя линиями она живёт**:

```json
{ "id": "top_ruffles", "span": ["shoulder", "waist"] }
{ "id": "bot_tutu",    "span": ["waist", "knee"] }
{ "id": "sh_heels",    "span": ["ankle", "sole"] }
{ "id": "acc_pearls",  "span": ["neck", "chest"] }
```

Дальше масштаб и позиция считаются сами: вещь растягивается так, чтобы её
верхний край лёг на первую линию, а нижний — на вторую.

Это работает без поштучной подгонки по одной причине: **у вещи, снятой
плоско, верхний край и ЕСТЬ линия плеч, а нижний — подол.** Поэтому регистрация
по умолчанию `[0, 1]` (весь bbox вещи) корректна для подавляющего большинства
предметов.

И главное: топ со `span: [shoulder, waist]` и юбка со `span: [waist, knee]`
встречаются на одной линии `waist` — стык получается по построению, а не
угадыванием.

Если у конкретной вещи в кадре есть запас (например, туфля снята с воздухом
сверху), это правится полем `reg` — где внутри своего bbox у вещи лежат её
собственные линии:

```json
{ "id": "sh_heels", "span": ["ankle", "sole"], "reg": [0.15, 1.0] }
```

Ширина по умолчанию не масштабируется отдельно — вещь сохраняет пропорции и
центрируется по осевой; `dx` двигает вбок (сумка, браслет).

## Порядок слоёв

Одна таблица на весь проект, как `z_positions.csv` у LPC — иначе стопку
невозможно держать в голове:

| z | слой | примечание |
|---|---|---|
| 10 | `hair_back` | масса волос за телом |
| 20 | `body` | база |
| 30 | `bottom` | низ |
| 40 | `top` | верх — поверх низа: заправлено, а не наоборот |
| 50 | `shoes` | обувь |
| 65 | `face` | мимика — на пустом лице базы |
| 68 | `makeup` | поверх мимики: помада ложится на губы, тени на веки |
| 70 | `hair` | причёска — поверх лица: чёлка на лбу |
| 80 | `acc` | аксессуары последними |

Предмет может занимать **два слоя на разных z** (длинные волосы: масса на 10,
шапочка на 70) — как многослойные ассеты у LPC.

## Что из этого следует для генерации

Генерация даёт вещь в случайном кадре, поэтому риг обязан быть **устойчив к
кадрированию**. Отсюда два правила:

1. Один и тот же суффикс в промпте на все предметы (кадр, фон, отсутствие
   человека) — чем меньше разброс на входе, тем меньше правок `reg`.
2. Всё, что является **частью тела** (лицо, макияж, волосы, сама база), не
   генерируется, а рисуется под риг: модель рисует отделимые предметы и
   стабильно проваливает части тела. См. `README.md`.
