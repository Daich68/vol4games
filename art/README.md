# Графика BABYLAND

55 предметов в шести слотах, каждый из своего источника. Задача конвейера не
«нарисовать», а **склеить разное в один набор**.

Главная мысль: цельность даёт не одинаковость источников, а **общий грейд в
конце**. Пятьдесят пять снимков из пятидесяти пяти студий никогда не совпадут
по свету, тону и резкости — но после одинаковой постеризации, дизера и
пережатия они читаются как один комплект. Бриф Ланы просит «немного сломанную
цифровую эстетику», и она же решает эту инженерную задачу.

## Генерация

Локальный ComfyUI, чекпойнт `sd_xl_base_1.0.safetensors` в `models/checkpoints`.

```bash
python tools/babyland_assets.py gen --model sdxl
```

`--only <id...>` — точечно, `--force` — поверх существующего, `--doll` — база.
Есть второй бэкенд `--model wan`: Wan 2.2 TI2V-5B при `length: 1` отдаёт один
кадр, то есть картинку, и не требует ни одной загрузки. Годится как запасной
путь, но **стилем не управляется**: одни и те же слова кидают его из контурной
раскраски в залитый блоб. Для вещей нужен SDXL.

**Чего генерация не даёт — базу куклы.** «Лысая, безликая, одна фигура, во весь
рост, на белом» лежит вне приоров модели, и отрицаниями волосы, лицо и одежду из
неё не вычесть: четыре захода дали обрезанный кадр, мужской анатомический
манекен, лист персонажа в трёх видах и чиби в платье. Поэтому база — рисованный
`doll/base.svg`, и `build` всегда предпочитает его сгенерированному PNG.

## Конвейер

```
art/babyland/raw/  →  trim → cut → fit → grade  →  public/art/babyland/  →  sheet
```

| этап | что делает | почему так |
|---|---|---|
| `trim` | срезает рамку | реальные исходники — часто скриншоты с тёмными полями, и оценка фона по краю на них врёт |
| `cut` | отделяет вещь от фона | для продуктового снимка на светлом фоне цветовая дистанция чище нейросети: нет «мыла» по краю и результат детерминирован. `--grabcut` — запасной путь для сложного фона |
| `fit` | сажает в коробку слота | каждый слот — прямоугольник в долях полотна куклы; per-item поправки `scale/dx/dy` нужны **всегда**, ни один найденный снимок не сядет идеально сам |
| `grade` | приводит к одному виду | постеризация + дизер + JPEG-пережатие; плюс тон: `pretty` уходит в розовое, `wrong` обесцвечивается |
| `sheet` | контактный лист | выбирать по картинке, а не по списку имён |

```bash
python tools/babyland_assets.py status
```
```bash
python tools/babyland_assets.py queries
```
```bash
python tools/babyland_assets.py build
```
```bash
python tools/babyland_assets.py sheet
```

Собирать по одной вещи: `build --only top_ruffles`. Манифест дописывается, а
не перезаписывается, так что `--only` не выкидывает из игры собранное раньше.
Промежуточные вырезы для разбора неудачного матирования: `build --debug`
(ложатся в `work/`).

## Что куда кладётся

- `art/babyland/catalog.json` — источник правды по **графике**: слот, вид
  (`pretty`/`wrong`), поисковый запрос, поправки посадки. Геймплейный источник
  правды — `src/games/babyland/items.js`; связь по `id`.
- `art/babyland/raw/<id>.jpg` — картинка «как нашлась». **Не в репозитории**
  (вес и лицензии), лежит локально.
- `public/art/babyland/items/<id>.png` — собранный слой на полотне куклы.
- `public/art/babyland/items/<id>.thumb.png` — превью для плитки гардероба.
- `public/art/babyland/manifest.json` — то, что читает игра.

Манифест **необязателен**: пока вещь не собрана, на её месте остаётся
плейсхолдер. Игра играбельна на любом проценте готовности арта — можно
собирать по одной вещи и сразу смотреть.

## Где брать исходники

`queries` печатает готовый запрос на каждый предмет — они написаны под формат
референсов Ланы: `product photo` / `flat lay`, `white background`. Дальше по
убыванию удобства:

1. **Сгенерировать.** Даёт полный контроль над «розовое против чёрно-белого»
   и сразу чистый фон. Для 55 однотипных продуктовых снимков это самый
   предсказуемый путь.
2. **Стоки со свободной лицензией** — Openverse, Wikimedia Commons, Pexels.
   Одежда «плоской раскладкой» там есть, но не всякая: розовую юбку с рюшами
   найти сложнее, чем чёрные ботинки.
3. **Снять самим.** Для аксессуаров (жемчуг, банты, пластырь, разводной ключ)
   это быстрее, чем искать.

**Правило:** в `raw/` не кладём то, на что нет прав. Скриншоты из брифа —
референс для художника, а не материал сборки.

## Посадка

Коробки слотов в `catalog.json → doll.slots` считаются от геометрии базы, а не на
глаз. Два механизма поверх этого:

- `align: "bottom"` у обуви — иначе из-под туфли торчит босая ступня; `"top"` у
  причёски и верха.
- поштучная `box` у предмета — аксессуары одной коробкой не описываются:
  диадема на голове, сумка у бедра, крылья за спиной.

## Маскировка нестыковок

Сгенерированные вещи и рисованная база никогда не сядут идеально. Решение —
не вылизывать посадку, а **заявить несовпадение средствами эпохи**: бриф просит
«немного сломанную цифровую эстетику», а референсы (флеш-одевалки нулевых) сами
мешают 3D-персонажа с векторным хромом.

1. **Белая вырубка по контуру** вещи — вещь становится наклейкой, а наклейка
   имеет право не совпадать с телом: её НАКЛЕИЛИ.
2. **Микро-перекос** ±1.3° / ±2.5 px, детерминированный по хешу id — наклеено
   вручную и чуть криво. Детерминированный обязательно, иначе вещь дёргается
   при каждой перерисовке.
3. **Деградация поверх СОБРАННОЙ куклы**, а не поверх каждой вещи: единый растр,
   дизер и сканлинии на композите — это и склеивает разные источники в одну
   дешёвую картинку.
4. **Блёстки на швах** — взгляд цепляется за искру, а не за стык слоёв.

## Мимика

Пять выражений (`faces/*.svg`) нарисованы руками и садятся на пустое лицо базы по
якорю `generation.face_anchor`. Генерировать их нельзя: пять генераций дадут пять
разных девочек. В игре мимика лежит поверх макияжа, но под причёской и
аксессуарами — накрашенное лицо обязано показывать выражение, а чёлка ложится
сверху.

## Чего конвейер не делает

**Дизайн базы куклы.** Структурно она есть (`doll/base.svg`: лысая голова, пустое
лицо, точные якоря слотов), но нарисована грубее вещей — толстый контур и плоская
заливка против тонкой иллюстраторской линии у сгенерированного гардероба. Наклейки
это смягчают, но не отменяют: базу надо перерисовать под язык вещей либо отдать
художнику. Конвейер примет любой файл, положенный на это место.
